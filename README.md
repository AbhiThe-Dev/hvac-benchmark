# HVAC Topology Discovery Benchmark

A small, reproducible case study comparing **information-gain (active)
selection** against **random**, **traversal-heuristic**, and **rule-based**
testing policies for recovering HVAC equipment topology (Brick `feeds`,
and secondarily `hasPoint`/`hasPart`) from a limited number of simulated,
possibly-noisy relationship tests.

## What this is, and is not

This project evaluates how many *simulated relationship tests* a policy
needs to reconstruct **asserted metadata already present in published
Brick models**. It does **not**:

- validate against real technician search behavior (no technician search
  sequences were observed or encoded — the "traversal heuristic" policy is
  a modeled assumption about unaided search order, described below);
- perform physical interventions, drive real hardware, or run a building
  physics / time-series fault simulator;
- provide statistically powered, cross-building generalization claims (see
  "Evidence level" in [`results.md`](results/results.md) once generated —
  this is a small case-study sample, not a statistically powered
  benchmark).

See [`results/results.md`](results/results.md) (generated by running the
benchmark) for the topology counts, per-topology outcomes, and explicit
statements about which comparisons are and are not supported by the data.

## Data source

Brick models are extracted from the LBNL Fault Detection and Diagnostics
(FDD) data sets, published as a
[Figshare collection](https://doi.org/10.6084/m9.figshare.c.6486349.v1)
(8 archives). Because each archive bundles a small Brick model together
with many gigabytes of unrelated time-series CSVs, files are located and
extracted via **HTTP range requests** against the ZIP central directory —
no archive is ever downloaded in full. See
[`src/hvac_benchmark/data/zip_range.py`](src/hvac_benchmark/data/zip_range.py).

Nine Brick files are extracted across the eight archives (one archive
contains both a simulated- and an experimental-system model, kept as
separate, separately-labeled configurations rather than merged). Only one
of the nine (`rtu_exp`) describes a real physical system; the rest are
simulation models (evidence in `graph/building_grouping.py`). File
checksums, source URLs, license/citation metadata, and the file-to-building
grouping evidence are written to `results/provenance.json` and
`results/file_to_building.json` on every run.

## Method summary

1. **Load & merge**: parse each Brick file with RDFLib; merge files proven
   (via source documentation) to describe the same physical building/plant
   into one graph before extracting relationships; exclude ambiguous
   groupings rather than guess. Build a typed NetworkX graph per verified
   topology, and separately generate 10 seeded synthetic AHU–VAV–zone
   graphs as a supplementary check.
2. **Hide the topology**: policies only see opaque node IDs, Brick types,
   and independently-available location metadata — never names, target
   relationships, true degree, or truth-derived orders.
3. **Candidates & priors**: generate candidate edges via Brick subclass
   reasoning + explicit physical compatibility rules (plus documented
   location exclusions); derive sparse priors from plausible-parent counts
   and type compatibility, without fitting to evaluated edges. A
   uniform-prior ablation is included.
4. **Simulated noisy tests**: a "test" is a simulated direct relationship
   query with a configurable false-positive/false-negative rate (0%, 5%,
   15%) — not a calibrated actuator or reachability simulation.
5. **Inference**: exact Bernoulli Bayesian updates + expected information
   gain for the independent-edge experiment; a structured belief for
   terminal-unit/zone `feeds` targets that couples candidate parents via a
   cardinality prior `exp(-λ(k-1)²)` (λ=1 default; 0/0.5/2 sensitivity),
   with marginals and information gain computed through cardinality
   dynamic programming.
6. **Policies** (same candidates/priors/observation model/reconstruction
   rule within an experiment): Active (max EIG), Random (seeded shuffle),
   Traversal heuristic (fixed equipment-class + location order), Rule-based
   (fixed compatibility ranking), plus a frozen initial-ranking control.
7. **Evaluation**: 30 paired seeds per topology × noise condition, run to a
   fixed budget without consulting ground truth for stopping; precision /
   recall / F1 / calibration / test-count trajectories recorded from step
   zero; threshold attainment (90/90 primary, 95/95 secondary) computed
   after the fact.

## Running it

```bash
uv run hvac-benchmark
```

This downloads (or reuses the cache in `data_cache/`) the Brick models,
builds all topologies, runs every experiment, and writes `results/` —
`results.md`, PNG plots, machine-readable trajectories (JSON), the
resolved configuration, provenance, file-to-building mapping, and
exclusions.

Useful flags:

```bash
uv run hvac-benchmark --help
uv run hvac-benchmark --skip-download   # reuse an existing data_cache/ only
uv run hvac-benchmark --quick           # fewer seeds, for smoke-testing
```

## Development

```bash
uv sync --group dev
uv run pytest                  # full suite, including a ~70s end-to-end pipeline run
uv run pytest -m "not slow"    # fast unit/fixture tests only (~1s)
```

Tests cover: exact Bayesian updates and expected information gain against
brute-force enumeration on tiny hand-built graphs; structured cardinality
marginals/information gain against exhaustive enumeration (and against the
independent-edge model at λ=0); candidate coverage and location-exclusion
logic; inverse-relationship normalization and documented class-alias fixes;
noise simulation reproducibility; threshold-attainment censoring (first vs.
sustained, explicit non-attainment); split-file merge fixtures (cross-file
relationships surviving merge, unresolved-grouping exclusion, and
duplicate-topology de-duplication); topology-leakage prevention in the
policy-visible view; noiseless exhaustive recovery and the active/frozen-
initial equivalence invariant; HTTP-range ZIP parsing and CRC validation
against an in-memory fixture archive; and a Figshare-unreachable fallback
path, plus a full (small) end-to-end pipeline run whose `results.md` output
is checked for the required disclaimer language.

## Limitations (see also `results/results.md`)

- Real-topology count is small (**one** real LBNL testbed; the other
  eight LBNL files are simulation models, see `graph/building_grouping.py`); this
  is a case study, not a statistically powered benchmark, and 30 seeds are
  variability *within* a topology, not additional buildings.
- Closed-world approximation: unasserted relationships are treated as
  absent for scoring purposes, even though correctly merged Brick models
  can still omit real, physically-present connections.
- The traversal-heuristic baseline encodes a modeled assumption about
  unaided search order, not observed technician behavior.

## Self-supervised connection pretraining (`hvac_benchmark.pretrain`)

Learns a reusable "what does a plausible HVAC connection look like"
representation from the real, unlabeled corpus (45 MORTAR buildings + the ORNL
FRP `rtu_exp` testbed = 46 real systems; no fault labels). Needs the optional torch extra: `uv sync --extra pretrain`.

```
uv run hvac-pretrain --folds 5 --epochs 40 --out-dir results/pretrain
```

**Task.** Hide 20% of each building's `feeds` / `hasPart` / `hasPoint` edges
(from message passing and degree features too), encode the remainder with a
2-layer relational GNN over Brick class-hierarchy features, and train to rank
each hidden edge above corrupted ones (half same-Brick-class "hard" negatives,
half same-category negatives; true edges never used as negatives).

**Corpus.** Only systems confirmed physical are "real": the 45 MORTAR
buildings and `rtu_exp` (ORNL's Flexible Research Platform, a lab testbed).
The other seven LBNL files (`sdahu`, `ddahu`, `rtu_sim`, `fcu`, `pfpu`, `sfpu`,
`chiller_plant`, `boiler_plant`) are simulation models per the documentation
inside each Figshare archive; the evidence is tabulated in
`graph/building_grouping.py`. `--include-simulated` adds them to *training
only* as a labeled ablation; evaluation is always on real held-out
buildings. Duplicates (`mortar_bldg30` == `mortar_smc`, `pfpu` == `sfpu`) are
found by WL hash and always share a CV fold.

**Outputs** (`results/pretrain/`): `encoder/` (weights, config, vocab,
metadata), `node_embeddings.npz`, `cv_report.json`, `cv_summary.txt`.

**Reuse.**

```python
from hvac_benchmark.pretrain.model import load_pretrained
from hvac_benchmark.pretrain.data import example_from_topology

model = load_pretrained("results/pretrain/encoder")
ex = example_from_topology(topology_graph, ontology, model.vocab, rdf_graph)  # rdf_graph optional
h = model.encode(ex)                                # (N, 64) node embeddings
logit = model.score(h, src_idx, dst_idx, rel=0)     # rel index into pretrain.data.RELATIONS
feats = model.edge_features(h, src_idx, dst_idx)    # (E, 256) for a downstream classifier
```

**Evaluation** is grouped 5-fold over buildings (train on other buildings,
score held-out ones) against a type-pair-frequency baseline and random, with
exact tie-aware metrics. `within_type` ranks only among nodes of the true
endpoint's Brick class, isolating structure from class compatibility.
See the module docstring in `pretrain/evaluate.py`.
