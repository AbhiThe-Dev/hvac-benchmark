# LLMs for Active Learning, Sequential Experimental Design, and Next-Best-Test/Question Selection in Diagnostic Settings

## Key Question 1: Has anyone used an LLM to *directly* select the next best test/question in a diagnostic workflow (medical or industrial), and how does that compare to a formal Bayesian/EIG baseline on the same task?

### Takeaway
Where head-to-head comparisons exist, LLMs asked to pick the next diagnostic question or test **on their own** diverge substantially from Bayesian-optimal (expected-information-gain / mutual-information) selection — in the one rigorous medical comparison found, alignment with the Bayesian-network-optimal query order was close to random. The strongest-performing systems in this space do **not** let the LLM make the selection decision itself; they wrap the LLM in an explicit EIG/entropy-reduction module (Bayesian Experimental Design, information-gain scoring, or a probabilistic model) that does the actual test/question selection, and that hybrid consistently beats both a plain LLM and non-LLM baselines.

### Cited Findings
- In a simulated chest-pain diagnosis study, GPT-4o's stepwise information-seeking sequence was scored against a Bayesian-network-derived, mutual-information-optimal query order using rank-biased overlap (RBO, 0–1 scale). Mean RBO was **uniformly low across diagnoses**: pneumonia 0.060, pulmonary embolism 0.097, acute coronary syndrome 0.069, pericarditis 0.076, other 0.068 — "no statistically meaningful differences between diagnoses," and the paper concludes the LLM "diverged substantially from normative probabilistic models and physician practice patterns." — [Simulated evaluation of LLM stepwise diagnostic reasoning with real-world chest pain encounters and Bayesian networks, PMC](https://pmc.ncbi.nlm.nih.gov/articles/PMC13037032/)
- Same study: GPT-4o systematically over-predicted rare life-threatening etiologies (baseline sensitivity 79.3%, specificity only 45.2%); physicians requested >10× more labs and >2× more vitals than GPT-4o did, while GPT-4o over-ordered imaging by 30%+ — evidence of a resource-allocation pattern quite different from either the Bayesian-optimal or human-clinician pattern. — [same source](https://pmc.ncbi.nlm.nih.gov/articles/PMC13037032/)
- ACTMED ("Timely Clinical Diagnosis through Active Test Selection") explicitly does **not** let the LLM choose the next test directly. Instead the LLM is used as a "surrogate simulator" to sample M hypothetical outcomes for each candidate test; a formal Bayesian Experimental Design module then computes the expected KL divergence between posterior and prior for each candidate and selects the test maximizing information-gain-per-cost. The paper reports this hybrid "consistently outperformed other feature selection methods" on hepatitis, diabetes, and kidney-disease diagnostic tasks (GPT-4o and GPT-4o-mini), even surpassing a full-information baseline on diabetes; a KL-based stopping rule cut the average number of tests to ~1.9 (hepatitis) down to ~1.09 (kidney disease) while retaining comparable or superior accuracy (~50% test reduction); clinicians judged 94.5±1.4% of the system's test choices "clinically reasonable." — [Timely Clinical Diagnosis through Active Test Selection, arXiv:2510.18988](https://arxiv.org/html/2510.18988)
- The same ACTMED paper separately evaluates an "implicit" condition — LLM reasoning about which test to order *without* the Bayesian/EIG machinery — and finds it "showed a strong bias toward globally optimal [population-level] features" rather than adapting to the individual patient, i.e., it behaves like a static guideline-follower rather than performing genuine per-case expected-information-gain reasoning. — [same source](https://arxiv.org/html/2510.18988)
- Active Preference Inference using Language Models and Probabilistic Reasoning likewise avoids direct LLM question-selection: it builds "a probabilistic model whose conditional distributions are defined by prompting an LLM," then a formal algorithm selects the question that "optimizes expected entropy and expected model change" (i.e., EIG). The paper reports the wrapped system "outperforms baselines with the same underlying LLM on task performance while using fewer user interactions" in an interactive shopping-preference task, explicitly framing unaided LLM question-generation as producing "uninformative" questions. — [Active Preference Inference using Language Models and Probabilistic Reasoning, arXiv:2312.12009](https://arxiv.org/abs/2312.12009)
- MedKGI ("Iterative Differential Diagnosis with Medical Knowledge Graphs and Information-Guided Inquiring") similarly separates concerns: a medical knowledge graph constrains what the LLM can claim, and a distinct "information-gain-based question selection" component chooses which question to ask next to "maximize diagnostic efficiency." Reported result: 30% average improvement in dialogue efficiency while maintaining state-of-the-art diagnostic accuracy versus strong LLM baselines. — [MedKGI, arXiv:2512.24181](https://arxiv.org/abs/2512.24181)
- In free-form (non-Bayesian-wrapped) LLM history-taking, question quality is reported to improve turn-over-turn — "LLMs asking questions during history-taking show higher information gain (IG) values in later turns than earlier ones" — but this is a within-model trend, not a comparison to an EIG-optimal policy, and doesn't establish that the LLM's per-turn choice is close to optimal. — [WebSearch synthesis of medical history-taking / entropy-reduction literature; no single primary source with a direct optimality comparison was found — flagged as weaker evidence]
- In the industrial domain, "LLM-as-an-Investigator" (evidence-first reasoning for technical/mechanical/electrical/hydraulic troubleshooting) has a "Solution Investigator Agent" that does ambiguity estimation, candidate-hypothesis generation with probability tracking, and "targeted clarification questioning to distinguish between competing explanations," continuing "until the evidence makes one candidate explanation stronger than the alternatives." The abstract reports it "identifies the problem more accurately than direct prompting and reasoning-only baselines" and reduces user-induced conversational bias, but **no explicit Bayesian/information-theoretic baseline comparison or quantitative metrics were extractable** from the accessible text — the question-selection mechanism appears to be LLM-driven judgment over a tracked probability vector rather than a formal EIG calculation, but this could not be confirmed from available excerpts. — [LLM-as-an-Investigator, arXiv:2606.13220](https://arxiv.org/abs/2606.13220) (Gap: primary text inaccessible past abstract level)

### Inferences
- The one clean, quantitative, same-task comparison available (chest pain / Bayesian networks) suggests that **unassisted LLM test/question selection should not be trusted as a substitute for a validated EIG engine** — RBO scores around 0.06–0.10 are close to what a random or naive heuristic policy might produce, not a near-optimal one.
- Across three independent hybrid architectures (ACTMED, Active Preference Inference, MedKGI), the pattern that "wins" empirically is the same one the user's HVAC system already implements: LLM as a component that feeds a formal Bayesian/EIG selector, not as the selector itself. This is the most directly transferable structural finding for the user's project — it validates the existing architecture rather than suggesting the EIG engine should be replaced or bypassed by an LLM decision.
- The "implicit" (unaided) LLM condition in ACTMED defaulting to population-level/guideline-style choices rather than case-specific EIG-optimal choices is a plausible failure mode to expect if an LLM were ever given direct control over next-test selection in the HVAC system: it would likely regress toward "textbook" diagnostic checklists rather than genuinely adapting to the specific unit's evidence so far.

### Gaps
- No industrial/HVAC-specific paper was found that runs the same kind of head-to-head LLM-vs-EIG comparison that exists for chest pain diagnosis. The PHM Society and arXiv industrial fault-diagnosis papers found (LLM-as-an-Investigator, digital-twin fault handling, CNC fault diagnosis with knowledge graphs) describe LLM-driven interactive diagnosis but none were confirmed (from accessible text) to benchmark against a formal EIG/mutual-information baseline the way the chest-pain and ACTMED papers do for medicine.
- Full quantitative tables for LLM-as-an-Investigator and MedKGI's underlying comparison methodology could not be extracted (PDF text-layer access issues); only abstract-level claims are reported above.

## Key Question 2: Is there work using LLMs to generate/refine the hypothesis space (candidate causes/explanations) that then feeds a *separate* formal decision-theoretic selection mechanism?

### Takeaway
Yes — this is a well-represented and apparently effective pattern in both medical and industrial diagnosis: LLMs are used for open-ended candidate generation (leveraging world knowledge to propose a broad differential or fault-cause list), while a distinct probabilistic/decision-theoretic layer tracks, ranks, and selects among those hypotheses. This role is explicitly praised as a strength — LLMs are described as good at broad, knowledge-grounded candidate generation and comparatively weak at the sequential-planning/selection step, which is consistently offloaded to a formal method.

### Cited Findings
- Zero-Shot Active Feature Acquisition via LLM-Elicitation explicitly separates roles by design: rather than asking the LLM to plan/select sequentially, the authors use "disciplined elicitation," querying the LLM only for "the unary deviations and pairwise co-variations that are the sufficient statistics of a Markov random field," explicitly stating this acknowledges "LLMs excel at knowledge retrieval but are weak sequential planners." A maximum-entropy closure step resolves ambiguity in what the LLM's beliefs imply. On a clinical IBD evaluation, the resulting top-k acquisition policy "markedly outperforms all existing methods," especially on diagnostically ambiguous cases, and the overall framework "outperforms the LLM both on real labels and on its own extracted beliefs" (i.e., beats naive LLM-only selection). — [Zero-Shot Active Feature Acquisition via LLM-Elicitation, arXiv:2606.18933](https://arxiv.org/abs/2606.18933)
- In interactive technical-support/troubleshooting diagnosis, LLM-as-an-Investigator generates "sets of plausible candidate solutions, with each candidate represented by a short textual description and an initial probability score," forming an initial hypothesis space that is then refined: "the agent updates the probability vector over candidate solutions based on the initial problem, full history of answers, and current set of candidate causes" after each new piece of evidence — a hypothesis-generation role feeding a (lightweight) probabilistic tracker. — [LLM-as-an-Investigator, arXiv:2606.13220](https://arxiv.org/abs/2606.13220); [WebSearch synthesis](https://arxiv.org/pdf/2606.13220)
- MedKGI grounds LLM-proposed diagnostic candidates in a medical knowledge graph "to generate diagnostic candidates based on verified disease-symptom relationships," specifically to counter the LLM's tendency toward "hallucinated medical content due to weak grounding," while a separate information-gain module does the actual next-question selection. — [MedKGI, arXiv:2512.24181](https://arxiv.org/abs/2512.24181)
- Clinicians and researchers note LLMs' "capacity to generate expansive differential diagnoses often exceeds the scope considered by individual human clinicians," i.e., breadth of candidate-hypothesis generation is a claimed relative strength, distinct from (and not equivalent to) picking the single best next test among those hypotheses. — [WebSearch synthesis of differential-diagnosis hypothesis-generation literature](https://dl.acm.org/doi/10.1145/3733155.3733192)
- In industrial root-cause analysis, "Meta-RCA" combines an LLM-determined knowledge graph with a Bayesian belief model — the LLM's role is again knowledge-graph/candidate-space construction, with belief updating and final ranking handled by the Bayesian layer. Relatedly, "AgentRCA" formulates root cause analysis as interactive, evidence-grounded reasoning where "candidate diagnoses are ranked" and the agent must track supporting and contradicting evidence in a hypothesis table before concluding — a structured hypothesis-tracking role rather than free-form LLM judgment. — [WebSearch synthesis; primary sources not independently fetched — see arXiv:2604.06171 "LLM-Augmented Knowledge Base Construction For Root Cause Analysis" and arXiv:2607.22385 "Agentic Root Cause Analysis through Evidence-Grounded Reasoning"] (Gap: not fetched in full; titles/URLs confirmed via search only)
- PRIM ("Prior-fitted Root cause Identification with Meta-learning") frames industrial root-cause analysis as "a Bayesian inference task over a prior of causal models," using meta-learning to produce "a meta-learned Bayesian posterior over graphs and functional mechanisms" — this is a non-LLM Bayesian baseline in the same problem space (useful as a comparison point even though it does not itself use an LLM). — [PRIM: Meta-Learned Bayesian Root Cause Analysis, arXiv:2605.08786](https://arxiv.org/html/2605.08786v1) (Gap: abstract-level only; not deeply verified)

### Inferences
- There is a fairly consistent design philosophy across independent teams (medical AFA, technical-support triage, industrial RCA): use the LLM for what it's good at — broad, world-knowledge-grounded candidate/hypothesis generation and unstructured-evidence interpretation — and keep a formal probabilistic or information-theoretic layer in charge of tracking, weighting, and selecting among those hypotheses. This is a second, independent line of evidence (beyond Key Question 1) supporting an architecture where an LLM proposes candidate HVAC fault hypotheses or refines the hypothesis space, while the existing Bayesian EIG engine continues to own test selection and stopping.
- The explicit framing "LLMs excel at knowledge retrieval but are weak sequential planners" (from the Active Feature Acquisition paper) is a crisply stated, citable rationale for why the HVAC system's Bayesian EIG engine should retain control of sequential test selection even if an LLM is introduced elsewhere in the pipeline (e.g., to propose diagnosis categories, interpret manuals, or generate hypothesis descriptions).

### Gaps
- Several of the most directly relevant industrial RCA papers (Meta-RCA, AgentRCA, LLM-Augmented KB Construction for RCA) were found only via search snippets/titles and were not fetched and verified in full text; their quantitative results and precise LLM/Bayesian division of labor should be treated as provisional pending direct verification.
- No paper was found that specifically studies LLM-generated hypothesis spaces for **HVAC or building-mechanical-system** fault diagnosis feeding a downstream Bayesian selector — the closest analogues are general industrial RCA, CNC fault diagnosis, and bearing-fault diagnosis.

## Key Question 3: Is there work on LLMs eliciting or calibrating priors for a Bayesian model, and how well-calibrated are LLM-elicited probabilities shown to be?

### Takeaway
Multiple independent studies show LLM-elicited probabilities (used as Bayesian-network priors/CPTs or graphical-model edge priors) reliably beat a uniform/uninformative prior and can match or exceed low-sample-size maximum-likelihood estimation, but they are consistently described as "better than nothing," not well-calibrated in an absolute sense, and the direct elicitation format matters a lot (asking for a full distribution in one shot outperformed asking state-by-state in one study). Authors explicitly caution against treating LLM-elicited priors as safe for safety-critical use without further calibration.

### Cited Findings
- "Extracting Probabilistic Knowledge from Large Language Models for Bayesian Network Parameterization" tested two elicitation schemes — SepState (querying each state independently, then normalizing) and FullDist (asking for the entire distribution in one shot, e.g. "(0.70,0.20,0.10)"). Both "outperform the uniform baseline in all non-reasoning models" (p<0.01 for GPT-4o, Claude, and others), but "SepState...consistently falls short of FullDist with a higher median KL divergence" — a somewhat counterintuitive result since one might expect a simpler per-state query to be more reliable. — [Extracting Probabilistic Knowledge from LLMs for Bayesian Network Parameterization, arXiv:2505.15918](https://arxiv.org/html/2505.15918)
- The same paper found that using **raw token probabilities** as a calibration signal "performs worse than random," while verbalized/structured elicitation does not have this problem — an important distinction for anyone tempted to use logprobs directly as a probability estimate. — [same source](https://arxiv.org/html/2505.15918)
- The paper's "Expert-Driven Priors" (EDP) framework blends LLM-elicited priors with observed data via pseudocounts (p_i = (αq_i + c_i)/(α + Σc_j)). With only 3 data samples, EDP "yields a lower BN KL divergence than...MLE-30" (i.e., LLM-informed priors with 3 samples beat maximum-likelihood estimation with 30 samples); across 80 real-world Bayesian networks (13 domains) with Hill Climbing structure learning, EDP averaged macro-F1 0.72 vs. MLE's 0.71, a difference that is "statistically significant (p<0.05)" specifically in low-data regimes, but "not statistically significant" once full data is available. — [same source](https://arxiv.org/html/2505.15918)
- Explicit caveats from the same paper: performance is domain-dependent (e.g., "GPT-4o demonstrated superior performance in medical contexts, whereas Gemini 1.5 Pro proved more adept at business applications"); accuracy degrades for nodes with more than 3 states or many parents; LLMs "may struggle to provide informed predictions for more complex queries"; social/demographic biases can propagate into elicited priors; and critically, the authors state "merely surpassing a uniform distribution does not inherently qualify these models for safety-critical applications," alongside an unresolved risk of training-data contamination inflating apparent accuracy on well-known benchmark networks. — [same source](https://arxiv.org/html/2505.15918)
- "LLM-Based Prior Elicitation for Bayesian Graphical Modeling" (Sekulovski et al.) uses an LLM to provide categorical inclusion judgments for variable pairs (rather than asking for raw probabilities directly), converting these into edge-specific Bernoulli/Beta-Bernoulli/Stochastic-Block priors for graphical models — a design choice the authors motivate by citing evidence that "LLMs can express well-calibrated meta-judgments when provided with concise and structured prompts," in contrast to direct numeric probability elicitation. — [LLM-Based Prior Elicitation for Bayesian Graphical Modeling, British J. Mathematical and Statistical Psychology (Wiley)](https://bpspsychub.onlinelibrary.wiley.com/doi/10.1111/bmsp.70045) (Gap: full text was inaccessible — 403 error — so this is drawn from search-summary text, not independently verified against the primary source)
- The same line of work reports that "isotonic regression can be applied to LLMs' verbalized probability estimates using ground-truth labels," which "shows reduced calibration error" — i.e., raw LLM verbalized probabilities need post-hoc recalibration against ground truth to be trustworthy, they are not well-calibrated out of the box. — [WebSearch synthesis of prior-elicitation literature](https://pubmed.ncbi.nlm.nih.gov/41910523/) (Gap: PubMed abstract page was not accessible directly — cookie wall — so not independently verified beyond the search-engine summary)

### Inferences
- The consistent theme — "beats uniform, doesn't beat calibrated" — suggests a viable, bounded role for an LLM in the HVAC system: using an LLM to set an *informative but not fully trusted* prior (e.g., over likely fault categories given equipment type, age, symptom description) is plausibly a net positive versus a flat/uniform prior, provided the resulting prior is treated as a soft nudge (e.g., blended via pseudocounts as in EDP) rather than as ground truth, and ideally recalibrated against the system's own historical outcome data (isotonic regression or similar) before being trusted.
- The elicitation *format* matters enough to be worth testing empirically rather than assumed (FullDist > SepState in the one paper that compared them) — this argues for a deliberate calibration/format study if the user's project ever adopts LLM-elicited priors, rather than picking a prompting format by intuition.
- No paper found here reports absolute calibration metrics (e.g., Expected Calibration Error, Brier score) for LLM-elicited Bayesian priors specifically — the evidence is all relative (vs. uniform, vs. MLE), which is useful but leaves an open question about how far LLM priors are from a truly well-calibrated ideal.

### Gaps
- No confirmed source gives a hard calibration number (ECE, Brier score, or similar) for LLM-elicited *priors* specifically (as opposed to general LLM confidence calibration, covered under Key Question 5). This is a meaningful gap for anyone trying to decide how much weight to give an LLM-elicited prior in a production Bayesian system.
- The Wiley/PubMed prior-elicitation papers could not be fully verified against primary text (paywall/cookie-wall issues) — findings from those sources should be treated as moderately, not fully, confirmed.
- No HVAC- or building-systems-specific prior-elicitation study was found (e.g., "given this equipment type and symptom, what's a reasonable prior over fault categories") — all found examples are medical, general graphical-modeling, or generic Bayesian-network benchmarks.

## Key Question 4: Is there work treating an LLM's own output as a noisy "evidence channel" combined with other evidence in a Bayesian update (LLM does not make the final decision)?

### Takeaway
Yes, and this is one of the more mature, production-oriented patterns found — particularly in industrial fault diagnosis, where at least one published hybrid architecture explicitly normalizes and bounds LLM outputs before they enter a formal belief-update equation, with the paper stating outright that LLM outputs are "not used directly for decision-making." Reported performance gains over both a non-LLM baseline and a pure-LLM baseline are large. This pattern is structurally the closest match to what the user is evaluating for their HVAC EIG engine.

### Cited Findings
- The "DML-LLM Hybrid Architecture for Fault Detection and Diagnosis in Sensor-Rich Industrial Systems" treats the LLM as a "constrained semantic interpreter," invoked only "when the system encounters information that cannot be interpreted through DML [rules] alone." Its output (a semantic inference plus confidence score) is passed through a "deterministic normalization function" Rn = N(R, C), then admitted into the diagnostic state update only if a stability constraint |D(t)−D(t−1)| < τ is satisfied; the diagnostic state equation is Dt = f(Dt-1, St, Ft, Rn), i.e., the LLM's normalized signal Rn is one bounded input among several (raw sensor state St, functional state Ft, prior diagnostic state Dt-1). The paper states explicitly: "LLM outputs are not used directly for decision-making...converted into quantitative or fuzzy state updates for downstream DML nodes." — [DML–LLM Hybrid Architecture, PMC](https://pmc.ncbi.nlm.nih.gov/articles/PMC13030379/)
- Reported quantitative comparison (SPC/FDC vs. pure LLM vs. DML-LLM hybrid): time-to-detection 7.4h → 3.1h → **1.2h**; F1 score 0.59 → 0.75 → **0.83**; provenance completeness 18% → 42% → **96%**; triage time per event 72min → 39min → **18min**. The hybrid beats both the traditional statistical-process-control baseline and a pure-LLM baseline on every reported metric, and by a wide margin on provenance completeness (traceability of the reasoning chain) in particular. — [same source](https://pmc.ncbi.nlm.nih.gov/articles/PMC13030379/)
- The architecture maintains two distinct LLM roles: an "internal" LLM constrained to structured inference during the reasoning/update loop, and a separate "external" LLM used only for natural-language explanation *after* the diagnosis is finalized, explicitly "without modifying decisions" — a clean separation between an LLM-as-evidence role and an LLM-as-explainer role. — [same source](https://pmc.ncbi.nlm.nih.gov/articles/PMC13030379/)
- More broadly, general sensor-fusion literature frames this as converting LLM text output into "noisy welfare/sensor-like indicators" that get fused probabilistically with other sensor streams, and separately notes that "probabilistic and Bayesian frameworks propagate uncertainty from input signals to final predictions, allowing models to express reduced confidence when inputs are degraded" — consistent with treating an LLM channel the same way one would treat any other imperfect sensor (with its own noise model), rather than as an oracle. — [WebSearch synthesis of LLM-augmented sensor fusion literature](https://www.mdpi.com/2079-8954/14/1/36) (Gap: general synthesis, not a single verified primary source with a quantitative noise-model spec)

### Inferences
- The DML-LLM paper is the strongest single piece of evidence in this whole research thread that "LLM as a bounded, normalized evidence input to an existing formal update rule" is a working, measurably beneficial pattern in an industrial fault-diagnosis setting structurally similar to HVAC diagnosis (sensor-rich, need for traceability/provenance, mix of structured sensor data and unstructured text like error messages/manuals). The explicit stability constraint (bounding how much a single LLM inference can move the diagnostic state) is a concrete, transferable design idea: an HVAC system could similarly cap how much an LLM-derived signal (e.g., interpretation of a free-text technician note, or a manual excerpt) is allowed to shift the posterior over fault categories in one step, preserving the EIG engine's role as the actual arbiter.
- The large provenance/traceability gain (18% to 96%) for the hybrid over the pure-LLM baseline is notable: it suggests that combining an LLM with a formal structured framework is not only more accurate but also substantially more auditable — likely a meaningful consideration for a system whose credibility depends on being validated and interpretable, as the user's Bayesian EIG engine already is.

### Gaps
- Only one primary, well-documented example of this "LLM as bounded/normalized evidence channel" pattern was found and verified (DML-LLM); it would be useful to find a second independent replication to confirm the ~2–4x performance gains are not paper/domain-specific.
- No paper was found that specifically models an LLM's evidentiary contribution with an explicit likelihood function or noise/error model (e.g., "LLM says X with implied reliability Y, so contributes evidence weight Z to the posterior") in the way a sensor's known error characteristics would typically be modeled in a rigorous Bayesian sensor-fusion setup — the DML-LLM paper's normalization/stability-bound approach is a practical engineering solution but is a looser guarantee than a principled likelihood model would provide.

## Key Question 5: What does the literature say about LLM reliability/calibration when reasoning about uncertainty, probabilities, or expected value directly — and what failure modes are relevant to using an LLM near a stopping-rule or test-selection decision?

### Takeaway
The literature is consistent and cautionary: LLMs are systematically overconfident when asked to directly quantify uncertainty (e.g., nominal 99% confidence intervals cover the true answer only ~65% of the time in one benchmark), and — more specifically relevant to a Bayesian pipeline — recent work shows LLMs are demonstrably *not* internally consistent Bayesian reasoners: they perform much better when uncertainty is externally structured for them (explicit prior + likelihood, step-by-step update) than when asked to integrate evidence and reason about probabilities on their own, and the authors of one such study state directly that "you cannot offload good statistical practice to an LLM." This is a direct, well-evidenced argument for keeping the HVAC system's formal Bayesian EIG engine as the actual decision/stopping mechanism, with any LLM component kept structurally separate and bounded (consistent with Key Question 4's findings).

### Cited Findings
- FermiEval-style evaluation: LLMs "excel at numerical estimation but struggle to correctly quantify uncertainty, and are systematically overconfident when constructing confidence intervals around their own answers" — nominal 99% intervals covered the true answer only ~65% of the time on average. — [LLMs are Overconfident: Evaluating Confidence Interval Calibration with FermiEval, arXiv:2510.26995](https://arxiv.org/pdf/2510.26995)
- "LLMs are not (consistently) Bayesian: Quantifying internal (in)consistencies of LLMs' probabilistic beliefs" is a directly on-point paper: when LLMs are given explicit prior beliefs and likelihoods and asked to update step-by-step ("Belief Propagation" mode), stronger models (e.g., GPT-5.1) achieve "near-optimal information processing." But when the same models are asked to integrate evidence more holistically/simultaneously ("batch mode"), they show "much higher rates of deviation from optimal information processing," and their implicit belief updates are "not consistent with their elicited likelihoods." — [LLMs are not (consistently) Bayesian, arXiv:2605.06915](https://arxiv.org/html/2605.06915v1)
- The same paper found a counterintuitive "task performance paradox": batch mode, despite being *less* Bayesian-consistent, sometimes achieved *higher* AUROC than the explicitly Bayesian step-by-step mode — the authors explicitly warn that "forcing Bayesian updating may in fact be harmful to task performance" in some domains including medical diagnosis, because implicit learned pattern-matching can outperform an LLM's poor explicit articulation of the correct update rule. Their bottom-line practitioner warning: "You cannot offload good statistical practice to an LLM" — LLM-produced likelihoods are "not tied to the world, not tied to the post-data distribution, or both." — [same source](https://arxiv.org/html/2605.06915v1)
- General calibration literature confirms overconfidence is closely tied to hallucination: "Overconfidence is a primary driver of hallucination," and "vanilla verbalized confidence exhibits significant overconfidence and poor failure prediction." Model scale helps somewhat — "as model capability scales up, both calibration and failure prediction performance improve, yet still fall far from ideal performance" — but larger models still "tend to overestimate their performance on challenging tasks and underestimate it on simpler ones," a pattern that mirrors human overconfidence biases rather than eliminating them. — [Mind the Confidence Gap / related calibration surveys, WebSearch synthesis](https://arxiv.org/pdf/2502.11028)
- Token-level (logprob) probability estimates are specifically flagged as unreliable for calibration purposes: in the Bayesian-network-parameterization study (Key Question 3), using raw LLM token probabilities as a signal "performs worse than random." — [Extracting Probabilistic Knowledge from LLMs for Bayesian Network Parameterization, arXiv:2505.15918](https://arxiv.org/html/2505.15918)
- A closely related paper, "Incoherent Beliefs & Inconsistent Actions in Large Language Models," was identified in search results as directly on-topic (title strongly implies LLM belief/action incoherence relevant to probabilistic decision-making) but its content could not be independently fetched/verified in this research pass. — [Incoherent Beliefs & Inconsistent Actions In Large Language Models, arXiv:2511.13240](https://arxiv.org/html/2511.13240v2) (Gap: not fetched; flagged for follow-up if a report-writer wants this thread deepened)

### Inferences
- The "Belief Propagation vs. batch mode" finding is arguably the single most important calibration-related finding for the user's specific use case: it implies that *how* an LLM is asked to participate in a Bayesian pipeline matters enormously. If an LLM is ever used to touch probabilities in the HVAC system, it should be constrained to narrow, explicit, step-by-step sub-tasks (e.g., "given this prior and this specific new sensor reading, estimate the likelihood of observing this reading under fault X" — a Belief-Propagation-style prompt) rather than being asked to reason holistically about "what's most likely going on" and implicitly produce a posterior or a next-test recommendation, since that holistic/batch-style prompting is exactly where the evidence shows the largest divergence from correct Bayesian behavior.
- The consistent overconfidence finding (both in Fermi-style estimation and general confidence-interval work) is a specific, well-evidenced argument against ever letting an LLM's self-reported confidence directly gate a stopping rule (e.g., "LLM says it's 95% confident, so stop testing") — that self-reported number is known to be systematically inflated relative to true accuracy, which is precisely the mechanism (confidence threshold) the user's existing EIG engine uses for its stopping rule. This reinforces that the stopping decision should remain with the calibrated Bayesian engine, not any LLM-reported confidence.
- Taken together with Key Questions 1 and 4, the literature converges on a single structural recommendation across every sub-thread examined: LLMs are consistently more reliable and more empirically validated as (a) hypothesis/candidate generators, (b) bounded/normalized evidence-interpretation modules feeding a formal update rule, or (c) narrowly-scoped probability-elicitation tools whose output is blended with data (never used raw) — and consistently less reliable when asked to directly perform the integrative, sequential, uncertainty-weighing judgment that a validated Bayesian EIG engine already performs well.

### Gaps
- No paper specifically studying LLM calibration/overconfidence *in the context of test-selection or stopping-rule decisions* (as opposed to general QA/estimation calibration) was found; the evidence here is extrapolated from adjacent calibration literature rather than a study of stopping-rule use specifically.
- "Incoherent Beliefs & Inconsistent Actions in Large Language Models" (arXiv:2511.13240) looked highly relevant by title but was not verified in this pass — worth a follow-up fetch if deeper detail on belief/action coherence is needed.
- No industrial/engineering-specific calibration study (LLM confidence when reasoning about equipment fault probabilities specifically) was found; all calibration evidence above comes from general-purpose or medical/estimation contexts and is being extrapolated to the industrial/HVAC domain by analogy, not direct measurement.
